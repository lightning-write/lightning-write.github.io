# 라이트닝 라이트

소설 원고용 편집기입니다. 인터넷이 없어도 열리고, 연결되면 구글 드라이브에 원고를 맞춰 둡니다.

- 코펍 바탕, 양쪽 정렬, 줄간격·들여쓰기 조절
- 글자 크기 슬라이더 하나: 글을 고르면 고른 부분만, 고르지 않으면 전체
- 메뉴를 접으면 종이만 남음 (Esc). 아래로 스크롤하면 펼치기 버튼이 숨음
- 장면 목록: 별표(＊)나 숫자만 있는 줄을 장면 구분으로 보고 목록을 만듦
- 휴지통(아이콘): 지운 원고는 30일간 보관 후 자동 삭제
- **열기(폴더 단추)** 는 네 묶음입니다. **편집 모드**(원고로 불러와 고침: HWP·HWPX·TXT·EPUB·백업), **읽기 모드**(보기만), **변환 모드**(문서는 EPUB으로, EPUB은 편집 가능 문서로), **번역 모드**(외국어 책을 한국어로 옮기며 읽기). 묶음마다 「이 기기에서」와 「드라이브에서」가 있고(마우스를 올리면 열 수 있는 형식이 뜹니다), 읽기 모드와 번역 모드 묶음에는 최근에 읽던 것 세 개가 「이어 읽기」로 붙습니다
- **저장(내려받기 단추)** 은 한글(.hwpx)·워드(.docx)·텍스트(.txt)·전자책(.epub)·PDF 다섯 형식을 **이 기기에 저장**과 **구글 드라이브에 저장** 두 줄로 고릅니다. 드라이브에서는 `LWRITE` 폴더에 원고마다 형식별로 한 파일(`제목.hwpx`, `제목.pdf` …)을 만들고, 다시 저장하면 그 파일을 고쳐 씁니다
- 원고는 먼저 기기에 저장되고, 드라이브에 연결해 두면 PC·휴대폰·태블릿이 서로 이어짐
- **읽기 모드**(열기 → 읽기 모드; 위쪽 「가−·가+」로 글자 크기를 바꾸면 이 기기에 기억하고, 편집기 글자 크기와는 따로입니다; PDF는 제외): HWP·HWPX·DOCX·TXT·PDF·EPUB(드라이브에서는 구글 문서도)을 열어 보기만 합니다(고칠 수 없음). 연 문서와 읽던 자리는 **서재**에 남아 읽기 모드 묶음의 「이어 읽기」로 다시 열 수 있고, 드라이브에 연결해 두면 다른 기기에서도 같은 자리부터 읽습니다(아래 「서재」). 옛 워드(.doc)와 잠금(DRM) 걸린 전자책·암호 걸린 PDF는 열 수 없습니다. PDF를 읽는 부품(pdf.js)은 처음 PDF를 열 때 받아 두고 그 뒤로는 오프라인에서도 씁니다
- **전자책(EPUB) 만들기**: 저장 → 전자책(.epub)으로 지금 원고를, 열기 → 변환 모드로 HWP·HWPX·DOCX·TXT(드라이브에서는 구글 문서도) 파일을(이 기기에서 여러 개를 고르면 묶음 .zip 하나로, 드라이브에 저장하면 한 권씩) EPUB으로 만듭니다. 본문은 한 글자도 고치지 않고, 장면 구분 별표는 가운데 + 위아래 한 줄, 장 제목이 있으면 장마다 차례에 넣습니다. 표지는 제목·작가 이름으로 자동으로 그리며(「다른 모양」, 「내 그림 쓰기」), 작가 이름은 이 기기에 기억합니다. 만드는 창에서 저장할 곳(이 기기 / 구글 드라이브)을 고를 수 있습니다. PDF → EPUB 변환은 없습니다
- **EPUB을 원고로**: 열기 → 변환 모드(또는 편집 모드)에서 EPUB을 고르면 새 원고로 열려 바로 고칠 수 있습니다. 책의 글은 빼지 않고 옮기며(구텐베르크 책의 앞뒤 안내·약관 글도 그대로), 제목 태그는 장 제목, 구분선은 별표 줄, 기울임·굵게는 그대로, 그림·책의 스타일·종이책 쪽 번호는 버립니다. 원고 제목은 책 제목입니다. 열린 뒤 뜨는 「한글 파일로 저장」이나 저장 메뉴로 한글·워드 파일을 만들 수 있습니다. 변환 모드에서 문서와 EPUB을 함께 고르면 문서는 EPUB 만들기 창으로, EPUB은 원고로 갑니다
- **번역 모드**: 아래 「번역 모드」
- **PDF로 저장**: 저장 → PDF. 인쇄 창 없이 앱이 바로 PDF 파일(A4, 쪽 번호, 양쪽 정렬, 글자 크기·줄 간격·들여쓰기는 앱 설정대로)을 만듭니다. 글꼴은 고른 본문 글꼴과 상관없이 **항상 코펍 바탕**입니다(다른 본문 글꼴은 파일에 넣을 수 없는 웹 글꼴이라서). 쓴 글자만 골라 넣어 파일이 가볍습니다
- **라이트닝**(앱 안에서 바로 AI를 부름, 무료 Gemini API): 번개(이어 쓰기), block/blocks, build(정리), bricks(조각함), 스토밍(8페이지즈 개요·인물표·연표), 위치 띠
- **글 종류**(소설·시나리오·산문): 「+ 새 원고」를 누르면 먼저 고르고, 아래쪽 표시줄의 글 종류 단추를 눌러 언제든 바꿉니다(정하지 않은 옛 원고는 소설). 번개와 build가 그 종류에 맞게 씁니다. 시나리오는 줄 단위로 새 줄에서 이어 쓰고, 산문은 글을 보고 메일·메모·칼럼을 알아서 구분합니다(메일과 칼럼은 날짜·금액·이름·수치를 지어내지 않고, 메모는 번호·글머리를 따라 항목을 잇습니다). 글 종류는 원고와 함께 드라이브로 오갑니다.
- 아이콘에 마우스를 올리면 이름과 하는 일이 말풍선으로 뜸

**주소**: https://lightning-write.github.io/

예전 주소 https://zax-zac.github.io/Wongo/ 는 2026년 11월에 이 주소로 옮겼습니다. 2026년 11월 13일부터 라이트닝은 claude.ai 페이지가 아니라 앱 안에서 돌아갑니다(아래 「라이트닝」).

## 설정 안내

처음 한 번만 하면 됩니다. 이미 끝낸 단계는 건너뛰세요. 1단계가 끝나면 바로 쓸 수 있고, 2단계까지 마쳐야 드라이브 동기화가 켜집니다. 지금 이 저장소는 1·2단계가 모두 적용되어 있습니다. 라이트닝(AI)은 저장소 설정이 아니라 기기마다 앱 안 **설정 → 라이트닝**에서 Gemini API 키를 넣으면 켜집니다(아래 「라이트닝」).

### 1단계. 웹 주소 만들기 (GitHub Pages, 2분)

1. 이 저장소에서 **Settings → Pages**로 갑니다.
2. **Build and deployment**의 Source를 **Deploy from a branch**로 둡니다.
3. Branch를 **main**, 폴더를 **/(root)**로 고르고 **Save**를 누릅니다.
4. 1~2분 뒤 같은 화면 위쪽에 주소가 나타납니다. 주소는 `https://아이디.github.io/저장소이름/` 형태이고, 저장소 이름의 대소문자가 그대로 들어갑니다.

이 주소를 한 번 열면 그다음부터는 인터넷이 없어도 열립니다.

### 2단계. 구글 드라이브 연결용 클라이언트 ID 받기 (약 15분)

모든 화면은 [Google Cloud 콘솔](https://console.cloud.google.com/)에서 원고를 저장할 구글 계정으로 로그인한 상태에서 진행합니다. 비용은 들지 않고 결제 정보도 필요 없습니다.

1. **프로젝트 만들기**: [새 프로젝트](https://console.cloud.google.com/projectcreate)에서 이름을 `wongo`로 하고 **만들기**를 누릅니다. 만든 뒤 화면 위쪽 프로젝트 선택에서 `wongo`가 골라져 있는지 확인합니다.
2. **드라이브 기능 켜기**: [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com) 화면에서 **사용**을 누릅니다.
3. **동의 화면 만들기**: [Google Auth Platform](https://console.cloud.google.com/auth/overview)에서 **시작하기**를 누르고 아래처럼 채웁니다.
   - 앱 이름: `라이트닝 라이트`, 사용자 지원 이메일: 본인 메일
   - 대상: **외부(External)**
   - 연락처 정보: 본인 메일
   - 정책 동의 후 **만들기**를 누릅니다.
4. **본인을 테스트 사용자로 넣기**: [대상(Audience)](https://console.cloud.google.com/auth/audience) 화면의 **테스트 사용자**에서 **사용자 추가**를 누르고 본인 Gmail 주소를 넣은 뒤 저장합니다. '테스트' 상태 그대로 두면 됩니다.
   - 다른 사람도 이 앱을 자기 구글 계정으로 쓰게 하려면, 그 사람의 Gmail 주소를 여기 테스트 사용자에 더합니다(최대 100명). 아래 「다른 사람이 쓰려면」을 보세요.
5. **권한 범위 넣기**: [데이터 액세스](https://console.cloud.google.com/auth/scopes) 화면에서 **범위 추가 또는 삭제**를 누릅니다. 아래칸 '직접 범위 추가'에 `https://www.googleapis.com/auth/drive.file`을 붙여 넣고 **표에 추가 → 업데이트 → 저장**을 누릅니다.
   - 이 범위로는 앱이 직접 만든 파일만 볼 수 있습니다. 드라이브에 있는 다른 파일에는 손대지 못합니다.
5-1. **(드라이브 파일 열기용) 읽기 권한 추가**: 같은 화면에서 **범위 추가 또는 삭제**를 다시 눌러 `https://www.googleapis.com/auth/drive.readonly`도 같은 방법으로 추가합니다. 열기 메뉴의 **드라이브에서**(편집·읽기·변환·번역)로 드라이브에 있는 파일을 고르려면 필요합니다.
   - 이 권한은 '고르기' 버튼을 누를 때만 따로 요청하고, 읽기만 합니다. 저장·동기화는 위의 `drive.file` 범위로만 합니다.
6. **클라이언트 만들기**: [클라이언트 만들기](https://console.cloud.google.com/auth/clients/create)에서 아래처럼 채우고 **만들기**를 누릅니다.
   - 애플리케이션 유형: **웹 애플리케이션**
   - 이름: `wongo-web`
   - **승인된 JavaScript 원본**에 `https://아이디.github.io`를 넣습니다. `/wongo`나 끝의 `/`는 붙이지 않습니다.
   - 승인된 리디렉션 URI는 비워 둡니다.
7. 화면에 나온 **클라이언트 ID**(`…apps.googleusercontent.com`으로 끝남)를 복사합니다.
   - 클라이언트 보안 비밀번호(secret)는 쓰지 않으니 어디에도 붙이지 마세요.
8. 클라이언트 ID를 이 저장소의 `config.js`에 넣습니다. 이 파일은 Claude가 대신 넣어 드릴 수도 있습니다.
   ```js
   window.WONGO_CONFIG = { googleClientId: '여기에-붙여넣기.apps.googleusercontent.com' };
   ```
   그리고 `sw.js` 맨 위의 `VERSION`을 하나 올립니다. 예: `wongo-v10` → `wongo-v11`.

이제 편집기를 열고 목록 아래 **드라이브 연결**을 누릅니다.
- 처음에는 "Google에서 확인하지 않은 앱"이라는 경고가 뜹니다. 본인이 만든 앱이므로 **계속**을 누르면 됩니다.
- 드라이브에 `LWRITE` 폴더가 생기고, 그 안의 `동기화 자료 (지우지 마세요)` 폴더에 원고가 저장됩니다. 2026년 11월 13일 전에는 폴더 이름이 `MYWONGO`였는데, 새 앱이 처음 동기화할 때 이름을 `LWRITE`로 바꿔 그대로 이어 씁니다. 아직 옛 앱인 기기가 `MYWONGO`를 새로 만들면, 새 앱이 그 안의 원고를 `LWRITE`로 옮겨 합치고 빈 폴더는 「LWRITE로 옮긴 뒤 남은 폴더 (지워도 됨)」으로 이름을 바꿔 둡니다. 폴더 이름은 드라이브에서 직접 바꾸지 마세요(앱은 이름으로 폴더를 찾습니다).

### 3단계. 휴대폰·태블릿에 앱으로 설치

- **아이폰·아이패드(Safari)**: 주소를 연 뒤 **공유 → 홈 화면에 추가**를 누릅니다.
- **안드로이드(Chrome)**: 주소를 연 뒤 **⋮ → 앱 설치** 또는 **홈 화면에 추가**를 누릅니다.
- **안드로이드(Edge)**: **≡ → 휴대폰에 추가**
- **PC(Chrome·Edge)**: 목록 아래 **앱으로 설치** 버튼을 누르거나, 주소창 오른쪽의 설치 아이콘을 누릅니다.

앱으로 설치해서 열면 처음부터 주소창이 없습니다. 브라우저 탭에서 열었을 때는 메뉴를 접어도 주소창은 그대로입니다(브라우저 전체 화면을 켜면 닫히지 않는 안내가 떠서 쓰지 않습니다).

## 쓰면서 알아 둘 점

- **저장**: 입력을 멈추고 1초 안에 기기에 저장됩니다. 드라이브에 연결되어 있으면 몇 초 뒤 드라이브에도 올라갑니다. Ctrl+S를 누르면 바로 올립니다.
- **오프라인**: 인터넷이 없어도 열리고 써집니다. 다시 연결되면 자동으로 드라이브와 맞춥니다.
- **한 시간마다 다시 연결**: 구글 보안 정책상 드라이브 연결이 한 시간 뒤 만료됩니다. 목록 아래 **다시 연결**을 누르면 됩니다. 그사이 쓴 원고는 기기에 그대로 저장되어 있습니다.
- **두 기기에서 동시에 고친 경우**: 원고가 사라지지 않습니다. 다른 기기의 내용이 「제목 (다른 기기 사본)」으로 따로 남으니, 필요한 부분을 옮긴 뒤 사본을 지우면 됩니다.
- **휴지통**: 지운 원고는 휴지통(아이콘)으로 가고 30일 뒤 자동으로 지워집니다. 그 안에는 복원할 수 있습니다.
- **이 기기 초기화** (설정 → 이 기기 초기화): 이 기기의 원고·휴지통·설정을 모두 지웁니다. 「초기화」라고 적어야 지워지고, 드라이브에 안 올라간 원고가 있으면 먼저 알려 줍니다. 기본으로는 드라이브 파일·드라이브 연결·Gemini 키를 남깁니다. 이 기기의 서재(읽던 문서·번역한 책)도 지워지지만 드라이브 서재에 있는 것은 다시 받아 옵니다. **드라이브의 원고도 모두 지우기**를 체크하면 드라이브 LWRITE 폴더의 원고·한글 파일·서재까지 휴지통으로 옮기고(30일 안엔 되살릴 수 있음), 다른 기기도 다음에 열 때 정리됩니다.
- **드라이브에 파일 저장**: **저장 → 구글 드라이브에 저장**에서 형식을 누르면 드라이브 `LWRITE` 폴더에 `제목.hwpx`(또는 .docx·.txt·.epub·.pdf)가 만들어집니다. 다시 누르면 같은 파일이 새 내용으로 바뀝니다.
- **데이터가 지워지지 않게**: 브라우저의 '사이트 데이터 삭제'를 하면 기기에 저장된 원고도 지워집니다. 드라이브에 연결해 두거나, 가끔 **모든 원고 백업**을 받아 두세요.

## 라이트닝 (앱 안의 AI)

앱이 직접 Google Gemini API(무료 등급)를 부릅니다. 서버도, claude.ai 로그인도 없습니다. 키는 기기마다 한 번 넣고, 그 기기의 브라우저에만 저장됩니다. 원고와 라이트닝 자료(조각·개요·인물·연표)는 지금처럼 기기와 드라이브에 있습니다.

**키 받기** (무료, 2분)
1. https://aistudio.google.com/apikey 를 **원고를 쓰는 구글 계정**으로 엽니다.
2. 「API 키 만들기」를 누르고, 이름·프로젝트는 그대로 둔 채 「키 만들기」. 나온 키를 복사합니다. 2026년부터 새 키는 `AQ.`로 시작합니다(예전 키는 `AIza`).
3. 앱의 원고 목록 아래 **설정**(톱니바퀴) → **라이트닝**을 열어 붙여 넣고 「확인」을 누릅니다. 키가 맞으면 모델 목록이 오고, 가장 새 **Flash-Lite** 모델이 골라집니다. 컴퓨터·휴대폰·태블릿마다 한 번씩 넣습니다.

**메뉴** (아이콘에 마우스를 올리면 이름과 하는 일이 뜹니다. 순서: 되돌리기·다시하기·서식·찾기·불러오기·내보내기 · block/blocks·build·bricks·스토밍)

| 이름 | 하는 일 |
|---|---|
| 번개 (오른쪽 아래 단추) | 커서 자리에서 이어 씁니다. Ctrl+Enter(맥 ⌘+Enter), 글 다음에 엔터 두 번으로도 됩니다. 나온 문장은 점선 밑줄이 있고, 고쳐 쓰면 밑줄이 사라집니다. 「다른 걸로」로 지운 제안은 그 자리의 '버린 방향'으로 기억해 다음엔 다른 길로 씁니다 |
| 따옴표·꺾쇠 | 직접 칠 때 `"` → “ ”, `'` → ‘ ’, `<제목>` → 〈제목〉, `<<책>>` → 《책》로 바뀝니다(lightning 설정에서 끌 수 있음). 번개가 쓴 대사도 원고의 따옴표 모양에 맞춥니다 |
| block / blocks | 번개 한 번에 나올 길이: 한두 문장 / 한 문단 (누를 때마다 바뀜) |
| build | 쓴 데까지(또는 고른 부분) 맞춤법·띄어쓰기·군더더기를 정리합니다. 바뀐 곳을 원문과 견주어 보고 받을 것만 고른 뒤 반영. 되돌리기 가능 |
| bricks | 떠오른 소재를 모아 두는 조각함. 번개와 build가 꼭 맞는 자리에만 씁니다 |
| 스토밍 | 브레인스토밍으로 8페이지즈 개요를 짜고(칸마다 바로 고치기·고정·말로 고치기·지난 판), 개요 완료로 인물표·연표를 만듭니다. 인물·연표를 고치면 개요에 저절로 반영 |
| 위치 띠 | 스토밍한 원고 위에 나타납니다. 남색 칸은 '지금 여기' 단계, 빨간 눈금은 커서까지의 분량이 목표 매수의 어디쯤인지. 칸을 누르면 그 단계가 펼쳐집니다 |
| 설정 (원고 목록 아래 톱니바퀴) | 펼쳤다 접는 두 칸. **라이트닝**: Gemini API 키, 모델, 번개 속도(빠르게·보통·공들여), 엔터 두 번 켜고 끄기, 키 지우기. **이 기기 초기화**: 아래 참고 |

**알아 둘 점**
- **무료 등급의 한도**: 분당·하루 요청 수에 제한이 있고 구글이 자주 바꿉니다. 2026년 가을 기준으로 Flash 계열은 하루 수십 회, Flash-Lite 계열은 하루 수백 회 수준이라, 앱은 Flash-Lite를 기본으로 고릅니다. 한도에 닿으면 「무료 사용량 한도에 닿았습니다」가 뜹니다. 한도는 미국 태평양 시간 자정(한국 오후 4~5시)에 다시 찹니다. 정확한 한도는 AI Studio의 Rate limits 페이지에서 내 프로젝트 기준으로 보입니다.
- **무료 등급과 원고**: 구글 약관상 무료 등급으로 보낸 내용은 구글이 제품 개선에 쓸 수 있고 사람이 읽을 수도 있습니다(유료 등급은 쓰지 않음). 번개는 커서 앞 3,000자 안팎과 조각·개요를, build는 정리할 부분과 앞뒤 문맥을, 스토밍은 브레인스토밍과 원고 발췌(앞 2,500자·뒤 3,000자)를 보냅니다. 원고 전체를 한꺼번에 보내는 기능은 없습니다.
- **키는 비밀**: 키를 아는 사람은 내 한도를 쓸 수 있습니다. 남에게 보내지 말고, 새면 AI Studio에서 지우고 새로 만드세요. 앱은 키를 generativelanguage.googleapis.com 에만 보냅니다.
- **모델이 없어졌을 때**: 구글이 모델을 내리면 「이 모델을 지금 쓸 수 없습니다」가 뜹니다. 설정 → 라이트닝에서 「확인」을 다시 눌러 목록을 새로 받고 고르면 됩니다.
- **퇴고는 claude.ai에서**: 이 앱의 AI는 초고를 밀고 나가는 데 쓰고, 꼼꼼한 검토·퇴고는 claude.ai 대화에서 합니다. 드라이브 `LWRITE/동기화 자료` 폴더의 원고 파일(.json, 본문은 html 칸)을 claude.ai의 Google Drive 커넥터로 읽히거나, **내보내기**로 받은 .txt/.hwpx를 올리면 됩니다.
- 스토밍 자료와 조각은 원고와 함께 드라이브로 오갑니다. 두 기기에서 따로 고쳤으면 조각은 합치고 개요는 더 나중에 고친 쪽을 씁니다.
- 드라이브의 '동기화 자료' 파일 이름 끝에는 원고 번호가 붙습니다(예: 「연필 공장 [mvu630zvxw7s].json」). 지우지 마세요.

## 번역 모드 (외국어 책을 한국어로)

열기 → **번역 모드**에서 EPUB·TXT·DOCX(구텐베르크에서 받은 영어 원서 등)를 고르면, 지금 펼친 장부터 라이트닝과 같은 Gemini 키·모델로 옮기며 보여 줍니다. 번역문은 오는 대로 화면에 채워지고, 아직 옮기지 않은 문단은 원문이 흐리게 보입니다. 다음 장은 미리 옮겨 둡니다.

- **보기**: 번역(번역문만) / 대조(번역문 아래 원문) / 원문. 차례는 위쪽 목록에서, 장 넘기기는 아래쪽 ‹ › 또는 키보드 ←·→. 다 옮긴 장은 차례에 ✓가 붙습니다
- **끝까지 번역**: 켜 두면 이 화면을 열어 둔 동안 책 끝까지 차례로 옮깁니다. 「멈추기」로 언제든 멈춥니다
- **표기·설정**: 사람·땅 이름 표기와 인물 사이 말투(존댓말·반말)를 모은 표입니다. 번역할 때마다 AI가 처음 나온 이름을 보태고, 고치면 다음 대목부터 따릅니다. 「이 장 다시 번역」은 표기를 고친 뒤 지금 장을 다시 옮깁니다(직접 고친 문단은 그대로). 남은 분량과 요청 횟수도 여기서 봅니다
- **고치기**: 켜면 번역문을 눌러 바로 고칩니다. 고친 문단은 다시 번역해도 바뀌지 않습니다
- **원고로**: 번역문으로 편집할 수 있는 원고를 만듭니다(다 옮긴 장만 / 책 전체 — 아직 옮기지 않은 곳은 원문 그대로). 만든 원고는 다른 원고처럼 드라이브로 오가고 한글·워드·EPUB으로 저장됩니다
- **이어 읽기**: 책과 번역·표기표·읽던 자리는 서재에 남습니다(아래 「서재」). 같은 파일을 다시 열거나 번역 모드 묶음의 「이어 읽기」를 누르면 이어지고, 드라이브에 연결해 두면 다른 기기에서도 이어집니다. 두 기기에서 같은 책을 번역하거나 고쳤으면 문단마다 더 나중에 바뀐 쪽으로 합칩니다. 지우기는 그 항목의 ✕(두 번 누름)나 표기·설정 창에서
- **번역 규칙**: 서술은 '-다', 대사는 인물 관계에 맞는 말투, 따옴표는 “ ”·‘ ’, 책·작품 제목은 〈 〉, 장 제목도 옮김(CHAPTER I → 제1장), 줄이거나 설명을 보태지 않음. 구텐베르크 책 앞뒤의 안내·약관 글은 옮기지 않습니다. TXT는 70자마다 끊긴 줄을 문단으로 잇고 `_기울임_`을 살립니다
- **한도**: 한 번에 원문 9,000자 안팎(한 장을 넘지 않음)을 보냅니다. 영어 장편 한 권(원문 50~70만 자)이면 요청 60~80번쯤이라, Flash-Lite 무료 한도라면 하루에 한 권 정도입니다. 한도에 닿으면 안내와 「다시」가 뜨고, 그때까지 옮긴 문단은 남습니다. AI가 옮기지 않겠다고 한 문단은 원문으로 두고 「번역 안 됨」을 붙입니다
- 무료 등급은 보낸 글을 구글이 제품 개선에 쓸 수 있습니다(위 「라이트닝」). 저작권이 끝난 책(구텐베르크)이면 걱정할 일이 없습니다. PDF와 잠금(DRM) 걸린 전자책은 번역 모드로 열 수 없습니다

## 서재 (이어 읽기)

읽기 모드와 번역 모드로 연 문서는 서재에 남습니다. 열기(폴더 단추) 메뉴의 읽기 모드·번역 모드 묶음 아래에 최근 것이 세 개씩 「「제목」 이어 읽기」로 붙고(읽기 문서는 쪽이나 %, 번역 책은 번역한 만큼이 함께 보임), 누르면 읽던 자리부터 엽니다. 더 오래된 것도 같은 파일을 다시 열면 이어집니다.

- **다른 기기에서 이어 읽기**: 드라이브에 연결해 두면 `LWRITE/서재 (지우지 마세요)` 폴더에 한 부씩 올라갑니다. 읽기 모드 문서는 원래 파일 그대로(PDF·EPUB·HWP 등), 번역한 책은 원문·번역·표기표를 묶은 파일 하나(`번역 · 제목 [번호].json.gz`)입니다. 다른 기기의 「이어 읽기」에는 「다른 기기에서」로 보이고, 누르면 그때 받아 옵니다
- **읽던 자리**: 문단 번호(PDF는 쪽)로 적어서, 화면 크기·글자 크기가 다른 기기에서도 같은 데서 시작합니다. 자리가 바뀔 때는 파일을 다시 올리지 않고 표시만 고칩니다. 두 기기에서 읽었으면 더 나중에 읽은 자리를 따릅니다
- **올리는 때**: 문서는 처음 열 때 한 번, 번역한 책은 번역하는 동안 1분 반에 한 번쯤과 번역 화면을 닫을 때, 읽던 자리는 몇 초 뒤. 드라이브 연결이 끊겨 있으면 이 기기에 두었다가 연결되면 올립니다
- **크기**: 5MB가 넘는 파일은 이어 올리기로 올립니다. 100MB가 넘는 문서는 드라이브에 올리지 않고 이 기기에만 둡니다
- **지우기**: 메뉴에서 항목 오른쪽 ✕를 누르면 「지우기」로 바뀌고, 한 번 더 누르면 이 기기와 드라이브(휴지통, 30일 안엔 되살릴 수 있음)에서 지우고, 다른 기기에서도 다음 동기화 때 사라집니다. 원고로 만든 것은 남습니다
- 같은 파일(내용이 같은 파일)을 다시 열면 같은 항목으로 이어집니다. 드라이브에서 연 파일도 서재에 한 부가 따로 올라갑니다

## 다른 사람이 쓰려면

자기 구글 계정이 있는 사람은 이 앱을 똑같이 쓸 수 있습니다. 원고는 각자의 구글 드라이브에, AI 한도는 각자의 Gemini 키에 따로 잡힙니다. claude.ai 계정은 필요 없습니다.

1. **앱 주인**: 그 사람의 Gmail 주소를 구글 클라우드의 테스트 사용자에 더합니다(위 설정 4번, 최대 100명).
2. **쓰는 사람**: 앱 주소(https://lightning-write.github.io/)를 열고 드라이브를 자기 구글 계정으로 연결합니다. 원고는 그 사람 드라이브의 `LWRITE` 폴더에 쌓입니다.
3. **쓰는 사람**: AI Studio에서 자기 Gemini API 키를 받아 **설정 → 라이트닝**에 넣습니다.
